# 接收与集成

## 核对当前交付条件

读取准确 Issue、候选 head／tree、base／target、两公司完整 PR 审查及必要测试和用户场景
证据。核对两方结论是否仍适用于当前对象，是否还有开放 P0/P1、关键证据缺口或未决定的
真实用户取舍。

检查当前合入／交付授权、停止状态、原写责任和真实依赖。多个 PR 涉及共享接口、状态或
用户路径时，核对具体消费者、可安全拆分的顺序和中间版本。

## 只补尚未被覆盖的集成风险

复用有效代码审查和验证证据。base、依赖、合入顺序、配置或目标环境变化时，定位新增的
组合风险和受影响证据，执行获准且必要的检查。

组合已审且不可变的成员时，可以复用有效成员结论，但组合仍须有自己的验证和独立接收
判断。集成修改代码、配置、依赖、启用方式或连接关系，使受审内容或证据适用性发生实质
变化时，即使测试通过且尚未发现缺陷，也须对差异与影响取得两方匹配的补充审查结论。
新的合并 PR 仍满足双审要求，可聚焦组合和新增影响；集成作者不能自签独立接收或通过。

发现会改变代码审查结论的新事实，交原审查双方核对受影响部分；发现代码缺陷，保留复现
证据并进入事实／影响核实流程，需要修复时由 Codex 事实核实会话执行。修复形成新候选后
重新核对其独立审查和测试。

候选环境可执行的关键用户场景应已在交付前完成。只有确实依赖实际部署、生产配置或外部
服务的项目保留为部署后补验；明确未验项影响的是哪一种交付或用户可用性声明。

## 执行与结果

执行合并或部署前核对当前候选、目标、授权和停止状态，完成后查回真实结果。
已发送但状态未知时查原对象，不另发替代动作；
外部状态与预期不同，保留观察和准确恢复建议，不自动回滚。

输出本次核对的对象、复用证据及其依据、新增组合检查、未解决命题和下一步。需要结论时使用：

- `PASS`：本次接收范围内无未解决的阻断问题，证据充分。
- `REWORK_REQUIRED`：需要修复候选、补审或补充验证证据。
- `OWNER_DECISION_REQUIRED`：事实已查清，仍需用户决定超出既有委托的取舍。

分别说明代码合入、候选接回、部署、场景实测和用户接受的实际状态。
