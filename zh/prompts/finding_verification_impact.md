# 独立影响核实

继续当前来自 OpenAI 以外另一家 LLM 公司的审核对话，只读核实双方报告中的阻断问题。
使用同一候选、Issue 和原报告；同一问题合并处理并保留出处。

沿真实输入、状态、调用方与用户入口，检查问题是否只是一个实例，是否还有同类入口、
相邻场景、持久化数据或跨模块组合受影响。核对实际触发前提与后果，不依据文件相邻、
import 关系或模型猜测扩大修复范围；发现事实核实前提有误时给出反证。

比较修复方案：怎样保留核心目标并减少必要改动，能否删除问题机制或复用已有能力，哪些
兼容、恢复或失败语义需要保留。指出必要的测试、用户说明和接口约定更新；复用一条组合
场景能证明多项问题时，说明它覆盖的范围。

风格偏好与未来功能单列为非阻断建议。

先完成本方核实，再与 GPT／Codex 原审核对话交流，最多三轮。实际回复对方报告，逐项说明
成立条件、代码或运行证据、反证及未检查项，区分实测与推断；说明维持或改变哪些判断。
证据充分且实质分歧已解决时可提前结束；绿色测试不能反证未覆盖的缺陷，三轮后仍有关键
缺口则列明补证动作，不因双方同意而通过。综合分析与修复由 GPT／Codex 原对话完成。

返回候选和问题引用、影响结论、最小修复范围及未决事项。核实结论使用 `PASS`（本批无未决
阻断问题且证据充分）、`REWORK_REQUIRED`（需要修复或补证）、`OWNER_DECISION_REQUIRED`
（事实已清，目标、关键行为或风险仍需用户取舍）；后者补回 Issue。
