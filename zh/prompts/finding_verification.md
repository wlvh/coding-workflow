# PR 阻断问题的核实、交流与修复

与 [公共约定](coding_common.md) 和本方核实用途提示一起装入。输入是一批需要处理的 PR
阻断问题、准确候选、适用 Issue、项目规则、两方正式审查报告和可核对的原始证据。
同一问题的不同表述合并处理，保留原报告引用；普通非阻断建议不单独启动核实批次。

## 先独立核实

Codex 负责事实核实，来自另一家 LLM 公司的 LLM 负责影响核实。双方从独立于作者、正式
审查者和另一核实方的新上下文开始，先完成自己的核实报告，再读取对方结论。使用同一
候选和问题批次；对象变化时明确新旧关系，不能混用不同版本的证据。

每项问题说明它成立所需的条件、代码或运行依据，以及成立、已被反证或仍待补证的判断。
已有绿色测试不能反证它没有覆盖的缺陷。技术事实不清楚时继续补证；真正需要改变目标、
关键行为或风险取舍的事项回到 Issue 与用户决定。

## 最多三轮证据交流

独立核实完成后，双方围绕分歧最多交流三轮，由 Codex 根据双方原始报告更新综合分析。
每轮记录收到的报告、实际补查的证据、维持或改变的判断，以及仍未解决的命题。双方确认
所依据的是同一候选；不能由 Codex 的综合文字替代另一方的实际回复。

证据充分且实质分歧已解决时可以提前结束。三轮后仍存在关键证据缺口或阻断分歧，保持
`REWORK_REQUIRED`，列出具体补证动作；不靠轮次、投票或模型身份推导通过。没有新证据、
已停止或达到实际资源边界时，保留原结果和下一步。

## 在 Codex 事实核实会话中修复

问题成立且修复方案明确后，Codex 在同一个事实核实会话中实施最小充分修复。实施前核对
实际授权、当前候选、工作区和写责任，完成与原写者的交接；原写入仍活跃或未知时先核清。
核实阶段保持只读，写入阶段由真实工具控制切换。

修复包含受影响实现、必要测试和文档，更新同一 PR 的 Review / Fix Record，记录原问题、
所采纳或排除的方案、代码变化和验证结果。优先复用已有测试及组合场景，不为批次中每项
问题机械新增一份测试。不得通过放宽需求或验收判据消除失败。

原会话无法恢复时，明确登记接续的新 Codex 会话，先依据原报告、代码和现场重新核实相关
事实，再在该会话修复；保留原记录，不将新会话冒充为原 session。

## 交回独立正式复审

修复形成新候选后，由来自两家不同 LLM 公司的正式 PR 审查者复审，并实际交流结论。
修复者不能签署自己的正式审核通过；复审会话与修复会话隔离。双方核对差异、影响和验收
证据，复用仍适用的完整初审材料，分别形成匹配当前候选的结论。

全批问题被反证时保留原候选，将核实依据交回正式审查者判断，不制造代码改动。复审出现
新的阻断问题时，保留新旧问题的关系，按新的准确候选接续核实。核实或综合结论本身不代替
两方正式审核通过。
