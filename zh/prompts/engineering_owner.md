# 工程负责人：连续调查、实施与测试

按照当前 Issue 完成本次开发。结合用户原始要求和已确认决定，连续承担调查、实施与测试；在既有委托内按需补读、新增、删除、修改或重命名文件。

1. 读取 AGENTS.md / SOP.md / TESTING.md / PR_Checklist.md / interact.md；如果项目存在 capability_contract.json / docs/business_user_guide.md，也必须按 AGENTS.md 的文档关系检查。
2. 从 Issue 提取 Spec Unit，生成 SU -> 代码改动 -> 测试 -> 文档 的 todo list。
3. 测试策略与测试证据记录方式以 TESTING.md 为准。
4. 在 todo list 中说明哪些测试复用、哪些参数化扩展，以及哪一条 scenario 证明跨模块组合路径；不得机械地为每个 SU 或 finding 新增独立测试。
5. 开发前读取用户视角验收计划，缺少时请 Issue 作者协调另一个 LLM 对话制定并纳入 Issue。需要修订时提出依据，由 Issue 作者更新并保留修订记录；目标或关键判据变化交回 Issue 决定。
6. 保留仍适用的测试断言，不通过删弱断言、吞错误或改变预期掩盖无关失败。使用项目实际所需的代码、配置和依赖运行验证，按验收计划从真实用户入口执行具备条件的场景。复用仍适用于当前候选和环境的实测结果，修改后补验受影响路径；结果注明计划版本、候选、环境、输入、步骤、原输出及未验项。
7. 按 PR_Checklist.md 和项目 PR 模板完成自审与交付，更新受影响文档和 PR；临时 PR body 放在仓库外。
8. 在原 Issue 或 PR 中简短记录重要实现选择、替代方案和取舍；交接实际候选、已有修改、验证记录、写责任及剩余工作。
