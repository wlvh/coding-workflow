# Codex 事实核实与同会话修复

继续当前使用 OpenAI LLM 的 GPT／Codex 审核对话，先只读核实双方报告中的阻断问题。
使用同一候选、Issue 和原报告；同一问题合并处理并保留出处。

核对问题是否真实存在、触发条件是否可达、完整因果路径、最小复现和严重度。阅读真实
实现、调用方与测试，必要时运行获准验证；区分实测、读码推断与尚未检查。检查同一问题
是否曾被修复，旧修复为何没有覆盖当前路径。

先完成本方核实，再与另一家 LLM 公司的原审核对话交流，最多三轮。逐项保留双方实际
回复、补查证据、维持或改变的判断、反证和待补证项，说明综合分析采用哪种解释及原因。
证据充分且实质分歧已解决时可提前结束；三轮后仍有关键缺口，列明补证动作并保持
`REWORK_REQUIRED`。已有绿色测试不能反证它未覆盖的缺陷；影响未核清时不能宣布修复范围完整。

问题成立且收到修复指示后，在本对话修复。接收原工程负责人的实际修改与验证记录，核对
当前候选和写责任；原写入仍活跃或结果未知时先核清。核对上游输入、当前模块、下游消费者
与相邻场景，选择最小充分改动；若删去不必要机制更直接，说明取舍并按有效目标实施。

复用或扩展已有测试和组合场景，更新必要文档及同一 PR 的 Review / Fix Record，记录实际
差异与验证结果。不得通过放宽需求或验收判据消除失败；目标、关键行为或风险取舍超出
既有委托时，交回 Issue 与用户决定。

修复后新开两家不同 LLM 公司的独立正式审核对话并交流结论；本修复对话不签正式通过。
全批问题被反证且代码未变时，由当前两方审核对话依据证据更新结论。

返回本批候选和问题引用、逐项事实结论、综合判断及未决事项；修复后另附实际差异与验证
记录。核实结论使用 `PASS`（本批无未决阻断问题且证据充分）、`REWORK_REQUIRED`（需要修复
或补证）、`OWNER_DECISION_REQUIRED`（事实已清，仍需用户取舍）。
