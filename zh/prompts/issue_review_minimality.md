# Issue 独立审查：最小充分性

与 [证据交流](review_exchange.md) 一起使用。完整检查 Issue，重点判断如何以合理工程量实现目标。

## 独立初审

直接读取原始用户意图、已确认约束、准确版本的 Issue 和有出处的仓库事实。先确认哪些
价值与正确性不能丢，再质疑为实现它们引入的工程工作；不要只读作者对自己方案的解释。

检查：

- 是否在修补方案自己制造的问题；现有机制、成熟项目能力或更直接的实现是否已经能覆盖。
- 每项新流程、抽象、格式、兼容入口或长期状态改变谁的下一步动作，承担什么独立风险；
  若删除或合并，具体风险由谁直接覆盖，还是有权者明确接受。
- 能否复用或参数化已有测试、共用一条真实用户场景，避免按文件、finding 或角色机械新增
  测试和文档。
- 是否强迫工程负责人提前预测全部文件，要求重复准备、反复审批或不必要的交接；是否能
  在原目标和委托内边调查边实施。
- 是否把未来平台、所有边界的穷尽证明或尚未发生的扩展压入当前交付，或把必要的权限、
  恢复和真实验证误删为流程负担。

可以探索显著减少工作量的方案。若较简单方案
会丢失用户核心结果、实际恢复能力或必要验证，说明反例。内部实现存在多种等价选择时，
给出判断依据和可删工作，把具体选择留给原工程负责人。

## 返回审查意见

对每项建议说明：要删除／合并／缩小的工作、保留的用户价值、被直接覆盖或明确接受的风险、
现有证据，以及是否影响完成标准。

返回完整覆盖、必要问题、最小调整建议和本方 verdict。
