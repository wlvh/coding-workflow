# 审查后的证据交流

本文件是 Issue 和 PR 两方审查者共用的后续阶段说明，随各自审查提示装入。
先完成各自独立初审，再执行本节；需要处理的 PR 阻断问题进入下文的核实与修复流程。

## 确认共同对象，再交流具体证据

先确认双方审查的是同一 Issue 内容版本，或同一 PR 的 head、base／target 和适用需求。
对象不同先说明差异，不能直接比较 PASS 或拼成共同结论。

双方初审均无阻断问题时，也交换结论，并各自简短确认同一对象、覆盖范围和有无遗漏；
这次确认留下实际交流记录即可，不必制造分歧或重复完整报告。

保留两方各自的初审报告和出处。将相同命题去重后，围绕真实分歧交换对应的用户原话、有效
政策、代码路径、原始测试输出或可复现反例。作者解释、他人 findings 和共享摘要是待核主张，
不能通过转发升级为事实。必要时只补查能区分两种解释的证据，不要求重复扫描全部无关材料。

每方独立说明自己维持或改变了哪些判断、依据是什么、仍有什么未检查；不能删除原异议、
修改另一方报告，或由一方替另一方签 PASS。共识与多数不证明正确，模型公司也不决定裁决。

## Issue 的处理

两方检查原始用户目标和同一草案，不分别产出两套实施方案。把有依据的缺口或精简建议
交给原 Issue 作者统一更新。原始目标不能为了容易通过审查而被偷偷缩小；工程方案也不能
借“完整性”无限扩张。更新后核对受影响命题，给出对应准确 Issue 版本的本方最终结论。

## PR 的处理

两方初审均覆盖完整 PR。共享重点用于发现相互遗漏，而不是让一方只审功能、另一方只审
复杂度，也不是让一方只验证对方的 findings。

将需要处理的阻断问题按同一候选归为一批，保留每项命题、证据和原始报告，交给
`finding_verification_fact` 与 `finding_verification_impact`：Codex 独立核实事实，另一家
LLM 公司的 LLM 独立核实影响，之后按 [核实流程](finding_verification.md)最多交流三轮，
由 Codex 综合证据。普通非阻断建议不因此启动核实批次。

成立问题在完成实际写责任交接后，由同一个 Codex 事实核实会话修复。你作为正式 PR 审查者
保持只读，核对修复后的真实 diff、受影响调用方和验收证据；复用对象与前提仍成立的旧调查，
补查失效部分，并各自形成适用于当前完整候选的正式结论。修复会话不能自签这次正式复审。
全批问题被反证时，根据原候选和核实证据形成结论，无需制造代码修改。仅关闭一个 finding、
对旧 head 的 PASS 或局部测试成功都不足以放行新候选。

需求、base、合并组合或环境变化同样按实际影响补审。无法确定旧证据是否仍适用时，明确
需要补查的范围；不无条件作废全部历史，也不无条件继承旧结论。

## 收口

每方最终报告保留本方 verdict、未决命题、原证据引用、改变判断的理由和适用对象。双方
有完整有效 PASS 且无阻塞问题，才可报告本轮双审通过；实际发布、合并与用户接受仍有各自
授权和事实条件。

证据不足继续标为 `REWORK_REQUIRED` 并给出补证动作，不靠重复轮次或投票收口。事实已清楚
而确有超出委托的目标、成本、风险或权限取舍，才将具体选择交用户并记回原 Issue。达到
资源或停止边界、且无法继续取得新证据时保留原结果和下一步，不制造新角色或强行一致。
