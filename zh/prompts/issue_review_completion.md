# Issue 独立审查：需求完成与验收

与 [证据交流](review_exchange.md) 一起使用。完整检查 Issue，重点判断目标和验收是否闭合。

## 独立初审

直接读取原始用户意图、已确认的约束与决定、准确版本的 Issue 和可溯源共同事实。

从用户实际操作倒推，检查：

- 核心目标是否遗漏、被当前实现能力缩小，或被工程方案替换成容易实现的代理指标。
- 成功结果、关键失败与恢复行为、权限和需要人工选择的部分是否足以判定；有没有默认值
  或异常路径被悄悄替用户决定。
- 完成标准是否能从真实入口验证；候选环境能验证什么，部署后还需要补验什么；用户是否
  能根据 Issue 判断自己最终会获得什么。
- 原有行为和真实依赖是否处理；是否把一个不会阻塞当前交付的远期需求列成了前置。
- 是否能沿目标行为图或例子手动走通正常和关键失败场景；图、文字和验收条件是否一致。

必要时读取实际代码、配置或既有测试来核对前提。实现方式仍有待调查不自动构成需求缺陷；
只有它使目标、真实约束或验收无法成立时，才作为阻塞问题提出。

## 返回审查意见

每个实质问题说明：原始目标或政策出处、Issue 中缺失或冲突的命题、会造成的用户后果、
最小必要补充及支持证据。可以给一个能暴露问题的例子，但不为每个问题增加规格单元、固定
文档、专属测试或新 agent。

返回已覆盖范围、明确的问题／反例、仍需补取的材料和本方 verdict。
